Save a record with an attestation signature attached.

**Trigger:** `xrpc.procedure:<nsid>`. **Needs:** `happyview-record`, `happyview-atproto`.

<Tabs syncKey="lang">
<TabItem label="Lua">

```lua
local time = require("internal.time")
local record = require("happyview.record")
local atproto = require("happyview.atproto")

function handle(input, ctx)
  local body = { text = input.text, createdAt = time.to_iso8601(time.now()) }

  local ok, sig = pcall(atproto.sign, body)
  if ok then
    body.signature = sig
  end

  local ref = record.create("xyz.example.post", body)
  return { uri = ref.uri, cid = ref.cid, signature = body.signature }
end
```

import time from "internal.time";

import atproto from "happyview.atproto";

export default async function handle(input, ctx) {
  const body = { text: input.text, createdAt: time.to_iso8601(time.now()) };

  try {
    body.signature = await atproto.sign(body);
  } catch {
    // No signature: the record is saved without one.
  }

  const ref = await record.create("xyz.example.post", body);
  return { uri: ref.uri, cid: ref.cid, signature: body.signature };
}

## How it works

1. Build the record body.
2. Sign it with `sign` on [`happyview.atproto`](/docs/reference/scripts/libraries). The `pcall` (Lua) or `try`/`catch` (JavaScript and TypeScript) lets the script work without a signer configured, where `sign` raises `NO_SIGNER`. Signing also needs a caller, which a procedure always has.
3. Attach the signature to the body as `body.signature`, then save the record with `record.create`. Declare `signature` in the record lexicon, so apps reading the record know the field exists.
4. Return the signature alongside the URI.

The signature's `$type` defaults to `games.gamesgamesgamesgames.attestation`. Set `ATTESTATION_SIG_TYPE` to use another type.

## Usage

The DPoP proof is signed per request; an app built on the [HappyView SDK](/docs/reference/sdk) gets this from its session.

## Use case

An attestation signature lets an app verify that a record was processed by your instance, for contributions, moderation decisions or data shared between instances. The signature covers both the record content and the author's DID, so it can't be replayed across users, and changing the record invalidates it.

See [Attestation signing](/docs/guides/attestation-signing) for setup and configuration, or [Verify a signed record](/docs/guides/recipes/signed-record-verify) for the read side.
