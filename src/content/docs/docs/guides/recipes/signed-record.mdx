Save a record with an attestation signature attached.

**Lexicon type:** procedure

```lua
local time = require("internal.time")
local record = require("happyview.record")
local atproto = require("happyview.atproto")

function handle(input, ctx)
  local body = { text = input.text, createdAt = time.to_iso8601(time.now()) }

  local ok, sig = pcall(atproto.sign, body)
  if ok then
    body.signature = sig
  end

  local ref = record.create(ctx.collection, body)
  return { uri = ref.uri, cid = ref.cid, signature = body.signature }
end
```

## How it works

1. Build the record body.
2. Sign it with `sign` on [`happyview.atproto`](/docs/reference/scripts/libraries). The `pcall` lets the script work without a signer configured, where `sign` raises `NO_SIGNER`. Signing also needs a caller: it fails when no account is signed in.
3. Attach the signature to the body as `body.signature`, then save the record with `record.create`. The record lexicon must allow a `signature` field, or the write is refused.
4. Return the signature alongside the URI.

The signature's `$type` defaults to `games.gamesgamesgamesgames.attestation`. Set `ATTESTATION_SIG_TYPE` to use another type.

## Usage

The DPoP proof is signed per request; an app built on the [HappyView SDK](/docs/reference/sdk) gets this from its session.

## Use case

Attestation signatures let clients verify that a record was processed by your HappyView instance — useful for contributions, moderation decisions, or cross-instance data where provenance matters. The signature covers both the record content and the author's DID, so it can't be replayed across users or tampered with.

See [Attestation Signing](/docs/guides/attestation-signing) for setup and configuration, or [Verify Signed Record](/docs/guides/recipes/signed-record-verify) for the read-side counterpart.
