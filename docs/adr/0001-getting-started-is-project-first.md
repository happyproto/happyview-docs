# Getting Started teaches a project built with hpy

Getting Started is for people building an app, and it follows one path: install `hpy`, create a project, run it locally with `hpy happyview dev`, add lexicons, scripts, triggers, jobs, plugins, auth and tests, then deploy it to an instance on HappyProto or a self-hosted one. Running your own server is a guide (Guides › Self-hosting), not a Getting Started step, and the dashboard has its own guide that pages link to where it is the only way to do something.

The old docs forked silently: the landing page and Testing taught a project on disk while Installation, Lexicons and Reacting to records taught clicking in a running instance's dashboard, and a reader following one could not use the other (dashboard scripts can't be tested). Teaching both side by side on every page was the alternative; it doubles every page and still leaves the reader to choose.
