Read and override instance settings, such as the app name, ToS URL, privacy policy URL or logo. A stored setting takes precedence over its environment variable while the instance runs. All endpoints require the `settings:manage` permission.

**Response**: `200 OK`

```json
[
  { "key": "app_name", "value": "My HappyView", "source": "database" }
]
```

Stored values come first, sorted by key. They include every stored row, such as the `logo_data` and `logo_content_type` rows the logo upload writes. They are followed by values from the environment or `happyview.toml` for known keys with no stored value; a key with neither appears nowhere, even when it has a default. `source` is `database`, `env` or `project`, or `platform` for a setting a [hosting platform fixes](/docs/reference/configuration#settings-a-hosting-platform-fixes). A fixed setting's stored row isn't listed.

### Known settings

| Key | Env var | Default | Description |
|-----|---------|---------|-------------|
| `app_name` | `APP_NAME` | --- | Application name shown in sidebar and OAuth consent screen |
| `client_uri` | `CLIENT_URI` | --- | Public URL for this instance, linked from OAuth consent screen |
| `logo_uri` | `LOGO_URI` | --- | External URL to a logo image |
| `tos_uri` | `TOS_URI` | --- | Link to terms of service |
| `policy_uri` | `POLICY_URI` | --- | Link to privacy policy |
| `backfill_concurrent_pds` | `BACKFILL_CONCURRENT_PDS` | `10` | How many PDS servers to fetch from simultaneously during backfill |
| `backfill_concurrent_dids_per_pds` | `BACKFILL_CONCURRENT_DIDS_PER_PDS` | `3` | How many accounts to fetch concurrently from each PDS |
| `backfill_concurrent_resolution` | `BACKFILL_CONCURRENT_RESOLUTION` | `100` | How many DID document lookups to run in parallel during PDS resolution |
| `backfill_retention_days` | `BACKFILL_RETENTION_DAYS` | `28` | Days to keep per-account detail from completed backfill jobs. `0` = keep indefinitely |
| `verbose_event_logging` | `VERBOSE_EVENT_LOGGING` | `false` | Log every record index, record skip, and successful script run (record, label, and XRPC) to the event log. `"true"` in any case turns it on, and a change takes up to 30 seconds to apply. High write volume, so recommended only for debugging |
| `feature.spaces_enabled` | `FEATURE_SPACES_ENABLED` | --- | Enables atproto spaces, which are off by default. When `"true"` (in any case), space endpoints are available. When absent or any other value, space endpoints return `404 FeatureDisabled` |
| `feature.spaces_pds_migration` | --- | --- | When `"true"` (in any case), a user signing in with a `space:` scope granted gets a job enqueued to move the space repos HappyView keeps for them to their PDS |
| `event_log_retention_days` | `EVENT_LOG_RETENTION_DAYS` | `30` | Days to keep event log entries and job logs. `0` = keep indefinitely. [Protected events](/docs/guides/event-logs#protected-events) follow `space_access_log_retention_days` |
| `space_access_log_retention_days` | `SPACE_ACCESS_LOG_RETENTION_DAYS` | `365`, or `0` while `event_log_retention_days` is `0` | Days to keep protected events and ended access grants. `0` = keep indefinitely |
| `feature.space_inspector_enabled` | `SPACE_INSPECTOR_ENABLED` | `false` | Turns the [space inspector](/docs/reference/admin/spaces#the-space-inspector) on when `"true"`, in any case. |
| `space_inspector_max_grant_minutes` | `SPACE_INSPECTOR_MAX_GRANT_MINUTES` | `60` | The longest an access grant can last, from `5` to `525600`. |
| `script_instruction_limit` | `SCRIPT_INSTRUCTION_LIMIT` | `1000000` | Instruction budget for a script run. `PUT` refuses a value outside 1000 to 1000000000 with `400 Bad Request` |
| `script_wall_clock_seconds` | `SCRIPT_WALL_CLOCK_SECONDS` | `10` | Wall-clock limit for a query, procedure, record or label script run, in seconds. Jobs have none. `PUT` refuses a value outside 1 to 300 with `400 Bad Request` |
| `script_metrics_enabled` | `SCRIPT_METRICS_ENABLED` | `true` | Record per-script run metrics for [`/admin/metrics`](/docs/reference/admin/metrics). `PUT` refuses anything but `"true"` or `"false"` with `400 Bad Request` |

## Upsert a setting

```
PUT /admin/settings/{key}
```

  body: JSON.stringify({ value: "My HappyView" }),
});
```

<TabItem label="cURL">

  -H "$AUTH" \
  -H "Content-Type: application/json" \
  -d '{ "value": "My HappyView" }'
```

</TabItem>

The body is `{ "value": "..." }`. The value is always a string, so send `"true"`, not `true`. Any key is accepted; the table above lists the keys HappyView reads. `logo`, `xrpc-proxy` and `telemetry` are routes of their own, so `PUT /admin/settings/telemetry` reaches the [telemetry](/docs/reference/admin/telemetry) endpoint, not this one.

**Response**: `204 No Content`. `400 Bad Request` when a script limit is out of range or `script_metrics_enabled` isn't `"true"` or `"false"`. A `telemetry.*` key returns `409 Conflict` where a hosting platform manages telemetry, and so does a key the platform fixes.

A change to `event_log_retention_days`, `space_access_log_retention_days` or `feature.space_inspector_enabled` is audited. Its [protected event](/docs/guides/event-logs#protected-events) is saved together with the setting, and if the event can't be written, the setting isn't changed. A delete is audited the same way.

## Delete a setting

```
DELETE /admin/settings/{key}
```

Removes the override; the corresponding environment variable or `happyview.toml` value (if any) takes effect again. Returns `404 Not Found` if no value is stored for that key, and `409 Conflict` for a `telemetry.*` key where a hosting platform manages telemetry, or a key the platform fixes.

**Response**: `204 No Content`

## Database info

```
GET /admin/settings/db-info
```

Returns database backend, connection pool sizes, and whether an instance restart is recommended to resize the backfill pool for current concurrency settings.

| Field | Type | Description |
|-------|------|-------------|
| `backend` | string | `"sqlite"` or `"postgres"` |
| `server_max_connections` | number \| null | Postgres `max_connections` setting. `null` for SQLite |
| `main_pool_size` | number | Current main connection pool size |
| `backfill_pool_size` | number | Current backfill connection pool size |
| `restart_recommended` | boolean | `true` if concurrency settings have changed and a restart would resize the pool |

## Upload or delete the logo

```
PUT /admin/settings/logo
DELETE /admin/settings/logo
```

`PUT` takes a `multipart/form-data` body whose first part is the image, and stores it as the instance logo. The logo is served publicly at `GET /settings/logo`, and is used in place of `logo_uri` while it is stored. The part's content type must be `image/*` and it must be at most 5 MB, otherwise the request is refused with `400 Bad Request`. `DELETE` removes the stored logo.

**Response**: `204 No Content` for both.
