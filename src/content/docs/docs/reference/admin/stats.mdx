## Record counts

```
GET /admin/stats
```

**Response**: `200 OK`

```json
{
  "total_records": 12345,
  "collections": [{ "collection": "xyz.statusphere.status", "count": 500, "indexed": true }]
}
```

`collections` has one entry for every record lexicon on the instance, with a `count` of `0` when it has no records. `indexed` is `false` for a record lexicon installed without indexing, whose collection nothing subscribes to or backfills. Returns `503 Service Unavailable` when a collection's records live in external record storage that can't be reached.

## Operator and client counts

```
GET /admin/stats/counts
```

Returns the number of operators (seats, including those with superadmin) and registered API clients. The client count includes `hvc_hpy`, the built-in client `hpy` signs in with. It is cheap to call often, unlike the record counts above. Requires `stats:read`.

## Jetstream status

```
GET /admin/jetstream/status
```

The live Jetstream consumer's state since the process started. Requires `stats:read`; the platform key may call it too. This route exists only when the instance's records come from Jetstream, which is the default.

**Response**: `200 OK`

```json
{
  "protocol": "v2",
  "host": "jetstream1.us-east.bsky.network",
  "connected": true,
  "compression": true,
  "dictionary_id": 3,
  "applied_seq": 18300422,
  "applied_time_us": 1793390000000000,
  "lag_ms": 412,
  "last_frame_ms": 1793390000498,
  "idle_ms": 14,
  "worker_queue_depths": [0, 2, 0, 0, 1, 0, 0, 0],
  "worker_busy_since_ms": [null, 1793390000100, null, null, null, null, null, null],
  "now_ms": 1793390000512
}
```

Unknown values are an explicit `null`: `protocol`, `host`, `dictionary_id`, `applied_seq`, `applied_time_us` and `lag_ms` are all `null` before the first connection or event, `last_frame_ms` before the current connection's first event, and `idle_ms` while disconnected, and the two worker arrays are empty until the worker pool starts.

| Field | Meaning |
| --- | --- |
| `protocol` | `v2` (`subscribeEvents`) or `v1` (`/subscribe`); `null` before the first connection |
| `host` | The Jetstream host from `JETSTREAM_URL` |
| `connected` | Whether a subscription is open now |
| `compression` | Whether frames arrive zstd-compressed |
| `dictionary_id` | The zstd dictionary in use, or `null` |
| `applied_seq` | The newest event that it and every event before it have been applied: the position saved for a restart. `null` on v1, which has no seq |
| `applied_time_us` | When Jetstream witnessed that event, in microseconds since the Unix epoch |
| `lag_ms` | Milliseconds from `applied_time_us` to now |
| `last_frame_ms` | When the current connection last delivered an event, in milliseconds since the Unix epoch |
| `idle_ms` | Milliseconds since the current connection last delivered an event, or since it connected when none has arrived yet. It grows on a connection that is open but silent, even before anything was applied; past `JETSTREAM_STALL_TIMEOUT_SECS` HappyView reconnects |
| `worker_queue_depths` | Events waiting in each worker's queue, one entry per `JETSTREAM_WORKERS`. The event a worker is applying or retrying is not counted |
| `now_ms` | Server time when the snapshot was taken, in milliseconds since the Unix epoch. Subtract `worker_busy_since_ms` from it rather than using your own clock |
| `worker_busy_since_ms` | One entry per worker: when its current event started, in milliseconds since the Unix epoch, or `null` when idle. An old value with an empty queue means the worker is stuck retrying |
