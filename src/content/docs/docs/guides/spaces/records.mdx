:::danger[Experimental]
This API is experimental and will change. See the [atproto spaces overview](/docs/guides/spaces) for context.
:::

Space records are stored separately from public atproto records. They use the `at://` scheme with a `space` path segment to distinguish them from public records:

```
at:// did:plc:abcdefghijklmnop1234567890 / space / com.example.forum / main        / did:plc:author / com.example.forum.post / abcdefghijklmnop1234567890
      └── space DID ───────────────────┘           └── space type ─┘   └── skey ─┘   └── author ──┘   └── collection ──────┘   └── rkey ────────────────┘
```

:::note
When a repo has moved to its author's PDS, HappyView forwards `createRecord`, `putRecord` and `deleteRecord` to that PDS. This bridge is deprecated. A write returns `403` when HappyView holds no session for the author.
:::

## Creating a record

The caller must be a member with `write` access. HappyView generates the rkey as a TID.

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
const response = await fetch("https://happyview.example.com/xrpc/com.atproto.space.createRecord", {
  method: "POST",
  headers: {
    "X-Client-Key": CLIENT_KEY,
    "Authorization": `DPoP ${ACCESS_TOKEN}`,
    "DPoP": DPOP_PROOF,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    space: "at://did:web:happyview.example.com/space/com.example.forum/main",
    collection: "com.example.forum.post",
    record: {
      $type: "com.example.forum.post",
      text: "Hello from the forum!",
      createdAt: "2026-05-09T12:00:00Z",
    },
  }),
});
interface CreateRecordResponse {
  uri: string;
  cid: string;
}
const data: CreateRecordResponse = await response.json();
```

`createRecord` always inserts a new record. If a record with the generated URI already exists, it returns `409 Conflict`.

| ------------ | ------------- | -------- | ---------------------------------------------------------------- |

```json
{

  "cid": "bafyrei..."
}
```

HappyView takes the author DID from the authenticated caller, so you can write records only as yourself and the URI's author component is always your DID.

`putRecord` performs an upsert: if a record with the same collection and rkey already exists for this author in this space, it's overwritten. Use `swapRecord` to prevent unintended overwrites (see [Optimistic concurrency](#optimistic-concurrency) below).

## Getting a record

The caller must be a member with `read` access, or present a valid [space credential](/docs/guides/spaces/credentials).

Members with `read_self` access can read only their own records. Reading another author's record returns `403 Forbidden`.

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts

  space: "at://did:web:happyview.example.com/space/com.example.forum/main",
  collection: "com.example.forum.post",
  rkey: "3k2abc",
});
const response = await fetch(
  `https://happyview.example.com/xrpc/com.atproto.space.getRecord?${params}`,
  {
    headers: {
      "X-Client-Key": CLIENT_KEY,
      "Authorization": `DPoP ${ACCESS_TOKEN}`,
      "DPoP": DPOP_PROOF,
    },
  },
);
interface GetRecordResponse {
  uri: string;
  cid: string;
  value: Record<string, unknown>;
}
const data: GetRecordResponse = await response.json();
```

**Parameters:**

| Field        | Type          | Required | Description                     |
| ------------ | ------------- | -------- | ------------------------------- |
| `space`      | string        | Yes      | The space containing the record |
| `repo`       | string        | No       | The author's DID                |
| `collection` | string (NSID) | Yes      | The record collection           |
| `rkey`       | string        | Yes      | The record key                  |

Without `repo`, HappyView returns the caller's own record when one exists, and otherwise the record whose author DID sorts first. A caller with a [space credential](/docs/guides/spaces/credentials) reads the repo its request is addressed to, and a `read_self` member reads only their own. Pass `repo` when several authors may use the same rkey.

**Response:**

```json

    "$type": "com.example.forum.post",
    "text": "Hello from the forum!",
    "createdAt": "2026-05-09T12:00:00Z"
  }
}
```

## Listing records

The caller must be a member with `read` access, or present a valid [space credential](/docs/guides/spaces/credentials). Members with `read_self` access list only their own records.

<Tabs syncKey="lang">
<TabItem label="TypeScript">

```ts
const params = new URLSearchParams({
  space: "at://did:web:happyview.example.com/space/com.example.forum/main",
  collection: "com.example.forum.post",
  limit: "20",
});
const response = await fetch(
  `https://happyview.example.com/xrpc/com.atproto.space.listRecords?${params}`,
  {
    headers: {
      "X-Client-Key": CLIENT_KEY,
      "Authorization": `DPoP ${ACCESS_TOKEN}`,
      "DPoP": DPOP_PROOF,
    },
  },
);
interface RecordEntry {
  collection: string;
  rkey: string;
  cid: string;
  // Only present when `includeValues` is `true`.
  value?: Record<string, unknown>;
}
interface ListRecordsResponse {
  records: RecordEntry[];
  cursor?: string;
}
const data: ListRecordsResponse = await response.json();
```

**Parameters:**

| Field           | Type    | Required | Default | Description                                   |
| --------------- | ------- | -------- | ------- | --------------------------------------------- |
| `space`         | string  | Yes      |         | The space to list from                        |
| `repo`          | string  | No       |         | Filter by author DID. Without it, an OAuth caller lists their own records and a [space credential](/docs/guides/spaces/credentials) lists every repo. |
| `collection`    | string  | No       |         | Filter by collection NSID                     |
| `limit`         | integer | No       | 50      | Max records to return (1-100)                 |
| `cursor`        | string  | No       |         | Pagination cursor                             |
| `reverse`       | boolean | No       | `false` | List newest first. By default the oldest record comes first. |
| `includeValues` | boolean | No       | `false` | Include each record's `value` in the response |

**Response:**

```json

  "records": [

      "rkey": "3k2abc",
      "cid": "bafyrei...",
      "value": {
        "$type": "com.example.forum.post",
        "text": "Hello from the forum!",
        "createdAt": "2026-05-09T12:00:00Z"
      }
    }
  ],
  "cursor": "MjAyNi0wNS0wOVQxMjowMDowMCswMDowMHxhdDovL2RpZDp3ZWI6aGFwcHl2aWV3LmV4YW1wbGUuY29tL3NwYWNlL2NvbS5leGFtcGxlLmZvcnVtL21haW4vZGlkOnBsYzphdXRob3IvY29tLmV4YW1wbGUuZm9ydW0ucG9zdC8zazJhYmM="
}
```

`value` is only present when `includeValues` is `true`. By default each entry carries only `collection`, `rkey`, and `cid`.

## Optimistic concurrency

`swapRecord` and `swapCommit` provide optimistic concurrency control to prevent lost updates when several writers change the same space.

### swapRecord

Pass the `swapRecord` field on `putRecord`, `deleteRecord`, or individual operations within `applyWrites`. The value is the CID of the record you expect to be replacing. If the record's current CID doesn't match, the operation fails with `409 Conflict`, and if no such record exists, with `404 Not Found`.

```json
{
  "space": "at://did:web:happyview.example.com/space/com.example.forum/main",
  "collection": "com.example.forum.post",
  "rkey": "3k2abc",
  "record": { "text": "updated safely" },
  "swapRecord": "bafyrei_old_cid"
}
```

### swapCommit

Pass the `swapCommit` field on `applyWrites` to assert the space's current revision. If another write has reached the space since you last read its state, the operation fails with `409 Conflict` before any writes are applied.

The space's current revision is `revision` in the space object returned by [`com.atproto.simplespace.getSpace`](/docs/guides/spaces/managing-spaces#getting-a-space). Only the space's creator, an operator with superadmin, or a caller with a space credential can read it there.

```json
{
  "space": "at://did:web:happyview.example.com/space/com.example.forum/main",
  "swapCommit": "3l2tkbx7225co",
  "writes": [...]
}
```

| `cursor` | string  | No       |         | A space revision. Lists only repos updated after it. Pass a previous response's `cursor`, or the last `spaceRev` already processed. |

**Response:**

```json
{
  "repos": [
    {
      "did": "did:plc:author1",
      "repoRev": "3l2tkbx7225co",
      "rev": "3l2tkbx7225co",
      "data": { "$bytes": "q83vEjRWeJC..." },
      "hash": { "$bytes": "q83vEjRWeJC..." },
      "spaceRev": "3l2tkbx7a2v4s"
    },
    {
      "did": "did:plc:author2",
      "repoRev": "3l2tkbwz4fa2k",
      "rev": "3l2tkbwz4fa2k",
      "data": { "$bytes": "3q2+7wABAgM..." },
      "hash": { "$bytes": "3q2+7wABAgM..." },
      "spaceRev": "3l2tkbx7a3k2s"
    }
  ],
  "cursor": "3l2tkbx7a3k2s"
}
```

| Field      | Type    | Description |
| ---------- | ------- | ----------- |
| `repos`  | array   | The repos on this page, in the order their updates were sequenced. A repo updated while paging can appear again on a later page. |
| `cursor` | string? | The `spaceRev` of the last repo on the page. Absent when the page is empty. |

Each repo carries `did`, `repoRev` (its revision as last reported to HappyView), `data` (its LtHash digest), and `spaceRev` (the space revision of its last update). `rev` repeats `repoRev` under the alpha lexicon's name, and `hash` repeats `data` under its name before proposal 0016. Both are deprecated, still served in v3 alpha, and removal is not yet scheduled.

To stay in sync, a syncer keeps the last `spaceRev` it processed and passes it as `cursor` on the next call. See [Receiving notifications](/docs/guides/spaces/notifications#receiving-notifications).

## Cross-service access

A service that is not a member, such as a syncer or feed generator, reads records with a [space credential](/docs/guides/spaces/credentials) in place of an OAuth session. The credential goes in an `Atproto-Space` authorization header, alongside an `Atproto-Space-Audience` header and an HTTP Message Signature by the credential's key:

```sh
curl 'https://happyview.example.com/xrpc/com.atproto.space.getRecord?space=at%3A%2F%2Fdid%3Aweb%3Ahappyview.example.com%2Fspace%2Fcom.example.forum%2Fmain&collection=com.example.forum.post&rkey=3k2abc' \
  -H 'Authorization: Atproto-Space <credential>' \
  -H 'Atproto-Space-Audience: did:plc:author' \
  -H 'Signature-Input: atproto-space=("authorization" "atproto-space-audience")' \
  -H 'Signature: atproto-space=:<base64 signature>:'
```

A credential grants read access to every repo in the space, and never grants write access. See [Using a credential](/docs/guides/spaces/credentials#using-a-credential) for the audience each method expects and full examples.
