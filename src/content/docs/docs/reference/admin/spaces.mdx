Browse the [atproto spaces](/docs/guides/spaces) on this instance for moderation. These endpoints give operators access to spaces they are not members of, so they live in the admin API rather than the space XRPC API.

## The space inspector

The space inspector is off by default. An operator with `settings:manage` turns it on with **Enable Space Inspector** under **System > General**, the `feature.space_inspector_enabled` [setting](/docs/reference/admin/settings), or [`SPACE_INSPECTOR_ENABLED`](/docs/reference/configuration#space-inspector).

While it's off, every route on this page answers `403 SpaceInspectorDisabled`, except these:

- [Space inspector status](#space-inspector-status)
- [List access grants](#list-access-grants), [Revoke an access grant](#revoke-an-access-grant) and [List a grant's reads](#list-a-grants-reads), so access can still be ended and audited
- [Space migration status](#space-migration-status)

Listing spaces and reading their metadata and members needs `spaces:read`. Reading a space's records or blobs needs `spaces:inspect` and an active [access grant](#access-grants) that covers the request.

Every grant, every revocation and every read made under a grant is written to the [event log](/docs/guides/event-logs#space-events) as a [protected event](/docs/guides/event-logs#protected-events). The grant or revocation is saved together with its event. Content is returned only after its read event is written. If the event can't be written, the request fails with `500` and nothing changes or is returned.

### Cookie reads come from the instance's own pages

Each content read is recorded against the operator making it. So [List records in a space](#list-records-in-a-space), [Get a blob in a space](#get-a-blob-in-a-space) and [List an account's records](#list-an-accounts-records) accept the dashboard's session cookie only from the instance's own pages. The browser has to send `Sec-Fetch-Site: same-origin`, or an `Origin` that is one of the instance's [domains](/docs/reference/admin/domains). Any other request with the cookie gets `403 Forbidden`.

API keys and other `Authorization` credentials are not affected. A browser that sends neither `Sec-Fetch-Site` nor `Origin`, such as Safari before 16.4, can't load blobs with the session cookie.

## Access grants

An access grant lets one operator read one space's contents, or one account's records, for a limited time. It records why. A grant lasts from 5 minutes to `max_grant_minutes`, and 60 minutes by default.

| `scope` | `target` | Covers |
| --- | --- | --- |
| `space` | A space id | Every record and blob in that space, from every author |
| `account` | A DID | That account's own records in any space, and the blobs its own records reference |

Only the caller's own active grants count. When more than one covers a request, the one expiring last is used. Within a space, an account grant covers [List records in a space](#list-records-in-a-space) only when its `repo` filter names the grant's DID. [List an account's records](#list-an-accounts-records) always needs an account grant for that DID, and a space grant never covers it.

### Create an access grant

```
POST /admin/spaces/access-grants
```

Requires `spaces:inspect`, and the space inspector on.

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `scope` | string | yes | `space` or `account` |
| `target` | string | yes | A space id for `space`, a DID for `account` |
| `reason` | string | yes | Why access is needed. Trimmed, then 1 to 2000 characters |
| `duration_minutes` | number | no | The grant's length, raised to 5 or lowered to `max_grant_minutes` when outside them. Defaults to 60, or `max_grant_minutes` if that's shorter |

## Space migration status

```
GET /admin/spaces/migration-status
```

How far each space's repositories have moved from HappyView-hosted copies to their authors' PDSes, and which PDSes support spaces. Requires `spaces:read`.

**Response**: `200 OK`

```json
{
  "spaces": [
    { "spaceId": "0b6c1f0e-…", "type": "com.example.forum", "skey": "main", "polyfill": 12, "migrating": 3, "native": 40 }
  ],
  "awaitingAuthorization": 5,
  "detection": [
    { "pds": "https://pds.example.com", "supported": true, "tier": "descriptor", "missing": [], "checkedAt": "2026-10-01T12:00:00Z" }
  ]
}
```

- `polyfill`, `migrating` and `native` count the space's repositories by where they're hosted: still on HappyView, moving, or on the author's PDS. A space with no repositories is not listed.
- `awaitingAuthorization` counts accounts whose repositories are still on HappyView and who haven't signed in with a session granting `space:` access, so they can't move yet.
- `detection` is what HappyView last found out about each PDS's support for spaces, and what it's `missing`. `tier` says how it found out: `descriptor` (the PDS lists its own methods), `probe` (inferred from how it answers a method that needs auth) or `unreachable` (HappyView couldn't reach the PDS, which says nothing about its support).
