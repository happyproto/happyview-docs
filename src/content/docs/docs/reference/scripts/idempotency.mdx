title: Create scripts may run more than once
description: The same record can reach a create script more than once, so write create scripts to be idempotent.
---

HappyView doesn't track which records a script has already handled. The same record can reach a create script more than once, so treat every create event as "this record exists now", not "this record is new".

This applies to any script that handles creates: a `record.create:<nsid>` script, and a `record.index:<nsid>` script when `input.action` is `"create"`.

## When it happens

- **Backfills.** A crawl reads each account's existing records and sends every one through the record script as a create, whether HappyView has seen it before or not. A replay sends each archived event with its own action, so its creates arrive again too. Running a backfill again, or backfilling a collection that is already indexed, delivers those creates again.
- **Retries.** A record script that fails is run again, up to 4 attempts in total. Anything the script did before it failed, such as an HTTP call or a write, happens again on the next attempt.
- **Dead-letter retries.** Retrying a dead-lettered event from the dashboard runs the script for that event again.
- **A busy database.** The script runs before HappyView stores the record. If storing it fails because the database can't be reached for a moment, such as a full connection pool or a dropped connection, HappyView delivers the record again once the database answers, and the script runs again. The instance doesn't restart for this. On an instance reading the network store, the records after it in the same batch are delivered again too, and a network store backfill that hits this fails and starts again from the beginning of the collection. This applies to update and delete scripts as much as to create scripts.

## Write create scripts to be idempotent

Running a create script twice for the same record should leave things the same as running it once.

- Write by key, and replace. Key anything you store on the record's URI, or on its DID and rkey, and overwrite it. A search index document whose ID is the record's URI is safe to write twice. A `POST` that adds a new row every time is not.
- Don't keep per-call counters. Adding one to a count each time the script runs will overcount. Count the records instead, for example with `db.records(collection):count()` in Lua, or store a set keyed by URI.
- Check before one-time side effects. Before sending a notification, a welcome email or a payment, check whether it has already happened for this record, and record that it did, keyed by the record's URI.
- Keep the return value deterministic. If the script rewrites the record, compute the result from the record alone, not from the time of the run or a random value, so a second run stores the same thing.

## Example

This create script mirrors records into an external index. It uses `PUT` to a URL built from the record's URI, so a second delivery overwrites the same document instead of adding another:

<Tabs syncKey="lang">
  <TabItem label="Lua">

```lua
local json = require("internal.json")
local http = require("happyview.http")

function handle(input, ctx)
  local id = input.uri:gsub("[^%w]", "_")
  http.put(ctx.env.INDEX_URL .. "/documents/" .. id, {
    headers = { ["Content-Type"] = "application/json" },
    body = json.encode({ uri = input.uri, did = input.did, record = input.record }),
  })
  return input.record or true
end
```

import http from "happyview.http";

export default async function handle(input, ctx) {
  const id = encodeURIComponent(input.uri);
  await http.put(`${ctx.env.INDEX_URL}/documents/${id}`, {
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ uri: input.uri, did: input.did, record: input.record }),
  });
  return input.record ?? true;
}

import http from "happyview.http";

interface RecordEvent {
  uri: string;
  did: string;
  record?: Record<string, unknown>;
}

export default async function handle(input: RecordEvent, ctx: { env: Record<string, string> }) {
  const id = encodeURIComponent(input.uri);
  await http.put(`${ctx.env.INDEX_URL}/documents/${id}`, {
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ uri: input.uri, did: input.did, record: input.record }),
  });
  return input.record ?? true;
}
