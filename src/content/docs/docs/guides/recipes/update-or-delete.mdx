A single endpoint that handles create, update, and delete based on the input fields.

**Lexicon type:** procedure

```lua
local db = require("happyview.db")
local record = require("happyview.record")

function handle(input, ctx)
  if input.delete and input.uri then
    record.delete(input.uri)
    return { success = true }
  end

  if input.uri then
    -- Update existing
    local existing = db.get(input.uri)
    if not existing then
      return { error = "RecordNotFound", message = "no record at that uri" }
    end
    local body = existing.record
    body.status = input.status
    return record.put(input.uri, body)
  end

  if input.delete then
    return { error = "UriRequired", message = "a delete needs the uri of the record" }
  end

  -- Create new
  return record.create(ctx.collection, input)
end
```

## How it works

1. If `input.delete` is truthy and `input.uri` is provided, delete the record with `record.delete`, which removes it from the caller's PDS and the local index.
2. If only `input.uri` is provided, load the stored body with `db.get`, change its fields, and write it back with `record.put`, which calls `putRecord`. If no record exists at that URI, return a `RecordNotFound` error.
3. If `input.delete` is set without a `uri`, return a `UriRequired` error rather than creating a record.
4. Otherwise, create a new record from the input with `record.create`.

`RecordNotFound` and `UriRequired` must be declared under `defs.main.errors` in the lexicon, as in `"errors": [{ "name": "RecordNotFound" }, { "name": "UriRequired" }]`, for the response to be a 400. An undeclared error is sent as an ordinary 200 response body.

## Usage

The DPoP proof is signed per request; an app built on the [HappyView SDK](/docs/reference/sdk) gets this from its session.

## Use case

This pattern reduces the number of endpoints your app needs by multiplexing create, update, and delete through a single procedure. The presence of `uri` and `delete` fields in the input determines the action.
